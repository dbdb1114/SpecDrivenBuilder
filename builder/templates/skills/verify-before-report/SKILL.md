# 보고하기 전에 확인하기

사용자는 코드를 읽지 않는다. "다 됐습니다"라는 말을 그대로 믿고 프로그램을 쓴다.
그래서 직접 실행해서 본 것만 "됐다"고 말한다.

## 언제

- 기능 하나를 끝냈다고 말하려 할 때
- 전체 작업을 끝냈다고 말하려 할 때
- 사용자가 "다 됐어요?", "이제 써도 돼요?"라고 물을 때

## 순서

1. `spec.md` 에서 지금 끝냈다고 말하려는 범위의 완료 기준을 찾아 목록으로 적는다.
   완료 기준이 따로 없는 기능은 "사용자가 이 기능으로 하려던 일이 되는가"를 기준으로 삼는다.
2. 프로그램을 실제로 실행한다. 코드를 읽고 "될 것이다"라고 판단하는 것은 확인이 아니다.
   - 화면이 있는 프로그램: 프로그램을 켜고, 사용자가 할 순서대로 눌러 보고 입력해 본다.
   - 화면이 없는 프로그램: 사용자가 넣을 법한 입력으로 돌려 보고 결과를 직접 본다.
   - 자동 테스트가 있으면 함께 돌린다. 테스트 통과만으로 완료 기준을 확인했다고 보지 않는다.
3. 완료 기준마다 셋 중 하나로 적는다.
   - 확인함 — 무엇을 넣었고 무엇이 나왔는지 한 줄
   - 안 됨 — 무엇이 기대와 달랐는지 한 줄
   - 확인 못 함 — 왜 못 했는지 한 줄 (예: 사용자의 실제 파일이 있어야 볼 수 있음)
4. "안 됨"이 있으면 보고하지 말고 고친 뒤 2번부터 다시 한다. 같은 문제를 세 번 고쳐도 안 되면 멈추고,
   무엇이 안 되는지와 시도한 것을 사용자에게 알린다.

## 보고 형식

`AGENTS.md` 의 용어사전에 있는 사용자의 말로 쓴다. 파일 이름·명령어·오류 문구를 그대로 붙이지 않는다.

- 된 것: 사용자가 이제 할 수 있는 일을 한 줄씩. 직접 확인한 것만 적는다.
- 직접 확인하지 못한 것: 항목마다 이유와, 사용자가 확인하는 방법을 적는다. 없으면 "없음"이라고 적는다.
- 써 보는 방법: 프로그램을 켜는 방법과 가장 먼저 해 볼 일 하나를 순서대로 적는다.

## 하지 않는 것

- 실행하지 않고 "됐다", "잘 동작한다"고 말하지 않는다.
- 일부만 됐는데 "완료"라고 말하지 않는다. 된 것과 남은 것을 나눠 말한다.
- 확인하려고 사용자의 실제 자료를 지우거나 바꾸지 않는다. 확인용 자료를 따로 만들어 쓴다.
