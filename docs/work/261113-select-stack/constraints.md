# 제약 — 작업 단위 B (select_stack · verify_stack)

출처: 세션 지시 (2026-11-13). 계획을 세우거나 고칠 때마다 다시 읽는다.

## 범위

- `select_stack`: 스펙 항목을 보고 기술 스택을 **버전까지** 정한다. 출력은 기술 스펙 항목(선택과 이유), 또는 부족한 정보 목록
  (결정 주체가 사용자이고 "아직 모름"인 스펙 항목을 추가). 질문 문장은 쓰지 않는다 — 무엇을 모르는지만 넘긴다.
- `verify_stack`: LLM 의 기억이 아니라 패키지 저장소의 실제 정보로 버전을 확인한다 (존재하는가, 안정판인가, 지원이 끝나지 않았는가,
  함께 쓰는 것끼리 맞는가). 맞지 않으면 실제 버전 정보를 들고 `select_stack` 으로 돌아간다.
  저장소에 접속하지 못하면 "검증하지 못했다"고 스펙 항목에 적는다. 검증한 것처럼 넘기지 않는다.
- 두 노드의 프롬프트와 테스트. 테스트에서 실제 저장소에 접속하지 않는다 (LLM 과 같은 방식으로 가짜를 주입).

## 건드리지 않는 것

- 막힌 파일을 고쳐야 하거나 범위 밖으로 나가야 하면 중단하고 묻는다 (다른 worktree 에서 동시 작업 중).
