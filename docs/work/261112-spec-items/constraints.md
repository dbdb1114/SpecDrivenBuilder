# 제약 — 작업 단위 A (PROMPT.md 에서 옮김, 2026-11-12)

## 범위
- 스펙 항목(이름 · 영역 · 결정 주체 · 상태 · 내용)을 빌더에 정의한다.
- `question-format.md` 의 규격을 전부 정의한다 (질문 묶음, 답 제출, 확인 화면, `visual`, `preview`). 이번에 안 쓰는 것도 모델은 지금 정의.
  LLM 응답은 이 규격으로 검증한 뒤에만 내보낸다. `id` 는 빌더 코드가 붙인다.
- `interview_user` 를 스펙 항목 기반으로 확장: 한 번의 LLM 호출로 항목 갱신 + 질문 묶음(1~10개), 용도를 가장 먼저,
  서로 독립인 질문만 한 묶음에, 종료 규칙(코드가 항목 상태로 판정), 종료 사유 3가지 기록.
- 묻는 노드의 실행 규칙: 자기 영역에 결정 주체 사용자 + "아직 모름" 항목이 있을 때만 묻는다.
- `generate_artifacts` 가 스펙 항목을 받아 스펙에 "사용자가 정한 것 / 작업자가 정하는 것"을 나눠 쓴다.
- CLI 가 질문 묶음을 번호 목록으로 그리고 답을 받는다. `visual` · `preview` 는 CLI 에서 무시.
- 그래프 뼈대: 노드 8개 등록, 엣지와 돌아가는 경로 3개 연결. 미구현 6개는 빈 노드(파일 하나, LLM 없음, 프롬프트 없음).
  B~G 가 쓸 State 키도 전부 선언. 빈 노드 docstring 에 읽을 키 / 채울 키.
- fake LLM 을 호출 순서가 아니라 노드별로 응답하게.
