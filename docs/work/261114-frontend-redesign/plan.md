## 1. 분석 (현재 상태)

- [확정] 시안 패키지 `docs/design/frontend-redesign/` 는 예전 빌더를 기준으로 쓰였다. 지금과 다른 점:

| 시안의 전제 | 지금 빌더 |
|---|---|
| 백엔드 API 없음 → 목을 둔다 (`/api/sessions/**` 제안) | `/api/runs/**` 가 있다. 타입은 `npm run gen:types` 로 생성돼 있다 |
| 질문은 문자열 하나, 한 번에 1개 | 질문 묶음(1~10개), 선택지 구조화, 여러 개 고르기, 고정 선택지 "알아서 정해 주세요", "그만 묻고 만들어 주세요" |
| 화면 5개 (홈 / 인터뷰 / 생성 중 / 다운로드 / 리뷰) | 확인 화면(`confirm_spec`)이 있고, 프로필 질문 · 디자인 질문(색 견본 · 배치 그림 · 미리보기)이 있다. 리뷰 기능은 없다 |
| 파일 5개 고정, 파일별 진행 상태를 1초마다 조회 | 산출물 수는 스킬 수에 따라 다르다. 생성은 요청 하나가 끝날 때까지 기다리는 방식이라 파일별 진행 상태가 없다 |
| `slug` 를 백엔드가 준다 | 없다. zip 파일명은 `<run_id>.zip` |
| 스타일 방식 · 라우팅 · 질문 구조화는 미결정 | 스타일은 CSS Modules 로 결정됨(`frontend/AGENTS.md`), 질문은 백엔드가 구조화해서 준다. 라우터는 없고 `?run=` 으로 실행을 이어 간다 |

- [확정] 지금 프론트엔드: `App.tsx` 가 `RunView.status`(question / confirm / stalled / done)로 화면 4개 중 하나를 고른다.
  상태는 `hooks/useRun.ts` 하나, 백엔드 호출은 `api/client.ts` 하나. 테스트 21개.
- [확정] `RunView` 는 지금 대기 중인 화면(질문 묶음 또는 확인 화면)만 준다. **지난 문답(`qa`)과 요청 원문(`request`)은 주지 않는다** —
  State 에는 둘 다 있다. 시안의 대화 목록과 "PROJECT 제목"은 새로고침하면 복원할 데이터가 없다.
- [확정] 질문 묶음 제출 뒤 응답까지 십수 초~1분이 걸린다 (LLM 호출). 그동안 화면은 요청 하나를 기다린다.

## 2. 시안 → 지금 빌더 매핑

| 시안 | 이번 구현 |
|---|---|
| 01 홈 | 그대로. "설계 시작" = `startRun`. 예시 칩 · 회전 단어 · 하단 띠 · 궤도 장식 포함 |
| 02 인터뷰 (대화) | 질문 묶음을 **대화처럼 한 질문씩** 보여 준다. 답하면 내 말풍선이 생기고 같은 묶음의 다음 질문이 바로 나온다(서버 왕복 없음). 묶음의 마지막 질문에 답하면 묶음 전체를 한 번에 제출하고 타이핑 점을 띄운다. 프로필 · 용도 · 디자인 질문이 모두 이 화면 |
| 답변 도크 | 선택지 카드(번호 + 문구 + 추천 배지) + "알아서 정해 주세요" 카드 + 직접 입력. 여러 개 고르는 질문은 "다음" 버튼. `can_finish` 면 "그만 묻고 만들어 주세요". 선택지의 `visual` 은 카드 안에 색 견본 · 배치 그림 |
| 미리보기 | `preview` 가 있는 묶음은 봇 말풍선에 미리보기 화면을 붙인다 (기존 `Preview` 컴포넌트를 새 테마에 맞춤) |
| 오른쪽 패널 "spec.md — 실시간 작성" | "지금까지 받은 답" 목록 (질문 → 답). 생성된 스펙처럼 보이게 하지 않는다 |
| (시안에 없음) 확인 화면 | 같은 2단 레이아웃. 왼쪽에 영역별 스펙 항목 카드와 "고칠래요" 토글, 도크에 "이대로 만들어 주세요" / "고른 항목 다시 답할게요" |
| 03 생성 중 | 확인 뒤 응답을 기다리는 동안: 스피너 + 스캔 라인 + "산출물을 만드는 중". 파일별 진행은 표시하지 않는다(데이터가 없다). 완료 응답이 오면 실제 파일 목록이 차례로 번쩍인 뒤 다운로드 화면으로 |
| 04 다운로드 | zip 다운로드(`<a href download>`), 실행 안내 3단계 + 복사 버튼, 파일 목록, 파일 내용 보기(읽기 전용: 탭 + 원문). `slug` 대신 폴더명 `my-project` 를 안내 문구에 쓴다 |
| 05 리뷰 | 만들지 않음 (제약). "미리보기·수정" 버튼은 "파일 내용 보기" 로 대체 |
| 중간에 멈춤(`stalled`) | 화면을 바꾸지 않고 도크 자리에 오류 문구 + "다시 시도" |
| 단계 표시 4개 | `01 아이디어 / 02 인터뷰 / 03 확인·생성 / 04 다운로드`. `RunView.status` 와 대기 여부에서 계산 (상태를 따로 두지 않음) |
| 라우팅 `/s/:id`, `/s/:id/done` | 라우터를 추가하지 않는다. 지금처럼 `?run=<id>` + `status` 로 화면을 고른다 — 화면이 서버 상태 하나로 정해지므로 URL 을 나눌 이유가 없고 의존성이 늘지 않는다 |

## 3. 정할 것 — 승인 때 답 필요

**Q. 지난 문답과 요청 원문을 API 가 주게 할까?**

1. **`RunView` 에 `request` 와 `qa` 를 추가한다 (추천)** — `builder/src/specbuilder/api/schemas.py` · `main.py` 의 `_view` 와 API 테스트를 고치고 타입을 다시 생성한다.
   State 에 이미 있는 값을 내보내기만 한다(노드 · 그래프 · LLM 호출 변화 없음). 새로고침해도 대화 목록과 프로젝트 제목이 복원된다.
   API 응답 모양이 바뀐다(필드 추가라 기존 화면은 깨지지 않음).
2. 백엔드를 건드리지 않는다 — 대화 목록과 제목은 화면이 떠 있는 동안만 유지하고, 새로고침하면 지금 묶음부터 다시 보인다. 프론트엔드만 바뀐다.

## 6. 계획과 달라진 점

- 화면 파일 이름: `StartPage` · `QuestionPage` · `ConfirmPage` 를 고쳐 쓰지 않고 `HomePage` · `StudioPage` · `DonePage` 로 새로 썼다.
  질문 묶음 · 확인 화면 · 생성 중이 시안에서 한 화면(같은 2단 레이아웃)이라 `StudioPage` 하나에 두었다.
  `ChatLog` · `AnswerDock` · `SidePanel` 은 따로 파일로 빼지 않고 `StudioPage.tsx` 안의 컴포넌트로 두었다 (이 화면에서만 쓴다).
- `components/Button` · `Notice` 는 새 화면에서 쓰지 않아 지웠다. `Visual` · `Preview` 는 코드를 고치지 않고, 쓰던 CSS 변수 이름을
  새 토큰에 이어 주었다 (`index.css`).
- "완료 응답이 오면 파일 목록이 번쩍인 뒤 다운로드 화면으로" → 다운로드 화면의 파일 목록이 들어오면서 차례로 번쩍이게 했다.
  생성 중 화면에는 실제 파일 목록이 없어(응답이 와야 안다) 그 화면에서 번쩍일 대상이 없다.
- 선택지 카드의 최소 폭을 시안의 200px 에서 240px 로 — 실제 선택지 문구가 길어 200px 에서는 4줄로 꺾였다.

## 8. 안 한 것 / 남은 것

- 시안의 "05 리뷰" 화면 (제약대로 제외).
- 선택지 카드 안의 색 견본 · 배치 그림은 브라우저에서 직접 보지 못했다 — 확인한 실행에서 디자인 질문이 미리보기 확인 질문으로만 나왔다.
  컴포넌트 테스트(`StudioPage.test.tsx` "선택지의 그림과 묶음의 미리보기를 그린다")로만 확인.
- 키보드만으로 끝까지 가는 흐름, `prefers-reduced-motion` 은 브라우저에서 따로 돌려 보지 않았다 [미확인]. 모든 클릭 대상은 `button` / `a` / `input` 이고
  `motion.css` 에 reduce 규칙이 있다.
- 지난 문답의 미리보기 질문 문장에 배치 설명과 색 코드가 그대로 보인다 (백엔드가 기록한 질문 문장 — `interview_design` 쪽).
- 한 번 답한 질문은 묶음을 보내기 전에 되돌릴 수 없다. 고치려면 확인 화면의 "고칠래요" 를 쓴다.
- 글꼴은 Google Fonts 에서 불러온다 — 인터넷이 없으면 시스템 글꼴로 보인다.
