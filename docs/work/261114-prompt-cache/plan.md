# 노드 프롬프트 캐시와 사용량 기록

## 1. 분석

- [확정] Claude API 로 한 사이클을 돌리면 호출이 8~10회이고, 호출마다 노드 프롬프트(노드당 6~10KB)가 통째로 다시 들어간다.
- [확정] 빌더는 호출별 토큰 사용량을 남기지 않아 어느 쪽(입력/출력)에서 비용이 나가는지 볼 수 없었다.
- [확정] Claude API 의 프롬프트 캐시는 앞부분 일치다. `system` 끝에 `cache_control` 을 붙이면 그 블록까지가 캐시된다.
  수명 5분(읽을 때마다 갱신), 쓰기 약 1.25배 · 읽기 Sonnet 5.5 기준 약 0.05배 (Claude API 문서).

## 2. 변경

| 파일 | 변경 |
|---|---|
| `builder/src/specbuilder/llm/client.py` | `AnthropicAPIClient` 가 `system` 을 캐시 표시가 붙은 블록으로 보낸다. 호출마다 사용량 한 줄을 남긴다 |
| `builder/tests/llm/test_client.py` | 위 두 가지 |
| `builder/AGENTS.md` | `system` 에 바뀌는 값을 넣지 말 것 |

- LLM 호출 수는 그대로다. `claude -p`(기본 수단)에는 영향이 없다.
- 캐시 표시는 모든 노드에 붙인다. 한 번만 불리는 노드는 혼자 쓸 때 쓰기 비용(프롬프트 몫의 0.25배)만 더 내지만 금액이 작고,
  5분 안에 다른 실행이 있으면 읽힌다. 노드별로 켜고 끄려면 `LLMClient` 규약을 바꿔야 해서 하지 않았다.

### 추가: 노드 이름과 호출 기록 (같은 날)

비용을 노드별로 보려면 누가 호출했는지가 필요해서 두 가지를 더 넣었다.

| 파일 | 변경 |
|---|---|
| `llm/client.py`, `graph/build.py` | `for_node(llm, 노드명)` 껍데기 — 사용량 줄에 `node=` 와 걸린 초가 찍힌다 |
| `llm/trace.py`, `llm/show_trace.py` (새 파일) | `SPECBUILDER_TRACE=1` 이면 호출마다 프롬프트·응답·사용량을 `output/_traces/<run_id>.jsonl` 에 남기고, 표와 전문으로 본다 |
| `tests/llm/test_trace.py` (새 파일), `.env.example`, `builder/AGENTS.md` | 위 동작과 사용법 |

기록은 기본으로 꺼져 있다 — 프롬프트에 사용자의 요청과 답이 그대로 들어간다. `uv run pytest` 253 passed.

### 한 사이클의 실제 사용량 — 2026-11-14, `claude-sonnet-5-5`, Claude API, 답은 빈 줄

두 케이스를 동시에 돌렸다 (서로의 캐시를 읽는다). 달러는 100만 토큰당 입력 2 · 출력 10 · 캐시 쓰기 2.5 · 캐시 읽기 0.10 으로 계산.

03-vague (화면 + 데이터베이스), 호출 9회, 111초:

| 노드 | 입력 | 캐시 쓰기 | 캐시 읽기 | 출력 | 초 | 달러 |
|---|---:|---:|---:|---:|---:|---:|
| interview_user ×3 | 3,810 | 4,988 | 9,976 | 2,263 | 18.0 | 0.0438 |
| interview_design ×3 | 7,941 | 0 | 23,361 | 1,454 | 11.7 | 0.0328 |
| select_stack | 2,227 | 0 | 3,968 | 984 | 7.9 | 0.0147 |
| select_skills | 3,181 | 2,024 | 0 | 418 | 4.1 | 0.0156 |
| generate_artifacts | 2,941 | 0 | 4,525 | 11,665 | 69.2 | 0.1230 |
| 합계 | 20,100 | 7,012 | 41,830 | 16,784 | 110.9 | 0.2298 |

04-no-screen, 호출 6회, 59초: 입력 7,374 · 캐시 쓰기 23,223 · 캐시 읽기 4,988 · 출력 8,465 → 0.1580 달러.

- **비용의 73% 가 출력이고, 그중 대부분이 `generate_artifacts` 한 번이다** (03: 0.123 / 0.230 달러, 시간도 69 / 111초).
- 캐시가 없었다면 03 은 0.3057 달러 — 캐시로 약 25% 줄었다. 응답 규격을 함께 보내는 실제 호출에서도 캐시가 맞는다 (위 `[미확인]` 해소).
- 04 는 대부분의 노드가 한 번씩만 불리고 캐시를 처음 쓰는 쪽이어서 캐시로 줄지 않았다 (0.1580 vs 캐시 없이 0.1558).
- 같은 사용량을 `claude-opus-5-5` 단가로 계산하면 03 은 0.46 달러, 04 는 0.32 달러다.

## 4. 안 한 것 / 남은 것

- 이 두 호출에서 출력(1,014 · 1,359토큰)이 캐시되지 않는 입력(77토큰)보다 훨씬 크다. 출력 단가가 입력보다 비싸므로 **비용의 대부분은 출력일 가능성이 높다** `[추정: 호출 2회]`.
  캐시는 입력만 줄인다. 한 사이클 전체의 사용량 줄을 모아 보고 다음 조치(effort, 출력 길이)를 정한다.
- 스펙 항목·문답 기록(호출마다 바뀌는 입력)은 캐시되지 않는다. 문맥을 덧붙이는 구조로 바꾸는 것은 프롬프트 변경이라 별도 작업이다.
- 케이스당 1회 실행이다. 답이 빈 줄(추천)이라 실제 사용자의 사이클보다 문답이 짧을 수 있다.
