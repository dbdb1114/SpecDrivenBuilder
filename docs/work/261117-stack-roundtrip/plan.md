  프롬프트는 "`missing` 이 있으면 `items` 는 빈 목록이어도 된다" 라고만 해서 모델이 둘 다 쓴다.

호출 기록에 남은 `select_stack` 입력 4개("다시 물을 수 있는가: 예")를 같은 입력으로 다시 보냈다. 전 3회, 후 4회씩.

| 입력 | | 돌아감 | 돌아갈 때 쓴 기술 항목 | 응답 길이 |
|---|---|---|---|---|
| 04-no-screen (2개 실행) | 전 | 6/6 — "아침 7시에 Mac 이 켜져 있는가" | 2~3개 (버려짐) | 555~796자 |

| 운동 기록 앱 | 전 · 후 | 0/3 · 0/4 | — | 약 1,300자 |

- 돌아갈지의 판단은 바뀌지 않았다. 돌아갈 때의 응답만 약 7분의 1로 줄었다.
- **버린 시도 3개** (같은 입력으로 4회씩):
  1. "스펙 항목으로 기본값을 정할 수 있으면 돌아가지 않는다" 를 넣음 → 04 의 Mac 질문이 0/8 로 사라졌다. 꺼져 있으면 프로그램이 아예 돌지 않는, 꼭 물어야 하는 질문이다.
  2. "묻는다 / 묻지 않는다" 를 예시와 함께 나눔 → 예시가 04 와 같은 상황일 때만 8/8 로 물었고, 다른 예시로 바꾸니 0/8. 판단이 기준이 아니라 예시를 따라갔다.
  3. "기본값으로 정할 수 있었다면 `missing` 을 비운다" 를 덧붙임 → 역시 0/8.
  그래서 판단 기준은 건드리지 않고 출력만 줄이는 한 줄로 했다.

## 4. 안 한 것 / 남은 것

- 사이클 전체(품질 회귀 세트)는 돌리지 않았다 — `select_stack` 호출만 같은 입력으로 비교했다. 뒤 노드의 입력은 바뀌지 않는다.
