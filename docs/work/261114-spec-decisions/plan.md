# 스펙의 결정 목록을 빌더 코드가 쓰기

## 1. 분석

- [확정] Claude API 로 한 사이클을 돌리면 비용의 73% 가 출력이고 대부분 `generate_artifacts` 한 번이다 (`docs/work/261114-prompt-cache/plan.md`).
- [확정] 생각에 쓰는 토큰은 출력의 약 7% 다 — 04-no-screen 9회 호출의 응답 글을 `count_tokens` 로 세어 출력에서 뺀 값.
  `generate_artifacts` 는 0 이었다. effort 를 낮춰도 줄일 것이 거의 없어 그 방법은 하지 않았다.
- [확정] 03-vague 산출물 13,007자 중 스펙의 "사용자가 정한 것 / 작업자가 정하는 것" 두 절이 1,588자(12%)이고, 내용은 입력으로 준 스펙 항목을 옮겨 적은 것이다.

## 2. 결정 (2026-11-14, 사용자 승인)

스펙의 결정 두 절만 빌더 코드가 스펙 항목에서 그린다. `AGENTS.md` 의 고정 섹션과 폴더별 `AGENTS.md` 는 그대로 LLM 이 쓴다 —
미결정 전제("템플릿 방식" vs "프로세스 가이드 방식")를 굳히지 않는다. 옮겨 적기는 글쓰기가 아니라 데이터 출력이다.

- LLM 이 빈 항목을 빠뜨리면 실행을 멈추지 않고 "기본값을 정하고 한 줄로 알린다" 는 줄을 넣는다 (작업자가 되묻지 않게).

## 5. 안 한 것 / 남은 것

- **"사용자가 정한 것" 의 문장이 사용자의 답 그대로다.** 전에는 LLM 이 문장으로 다듬었다 ("단톡방 없이도 날짜와 회비 상황을 한눈에 볼 수 있다").
  이제는 고른 선택지 문구가 그대로 들어간다 ("잘 됐다고 볼 기준: 두 가지 모두 편해져요"). 질문 없이 읽으면 뜻이 흐린 답이 있다.
  고치려면 선택지에 "항목 내용이 될 문장"을 따로 두어야 한다 (공통 항목은 이미 그렇게 한다) — 규격 변경이라 별도 작업.
- 케이스당 1회. 01 · 02 는 돌리지 않았다. Codex 실행 검증은 하지 않았다.
- 첫 "후" 실행 2건은 세 번째 호출 뒤 응답 없이 멈춰 10분 제한에 걸렸다. 다시 돌리니 정상이었다. 원인은 확인하지 못했다 `[미확인]` — 두 실행이 같은 때 멈춘 점으로 보아 API 쪽 지연으로 추정.
