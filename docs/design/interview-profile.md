# Interview 노드 — 사용자 프로필 수집

> 결정 (2026-11-03): 빌더가 생성하는 AGENTS.md에 "작업자 컨텍스트" 섹션을 포함한다.
> 이 섹션을 채우기 위해 interview 노드 초반에 사용자 프로필을 수집한다.
> 레퍼런스 구현: 루트 `AGENTS.md` 의 "작업자 컨텍스트" 섹션 (개발자 버전).

## 왜

작업자는 사용자가 누구인지 모르면 설명 수준·용어·질문 빈도를 맞출 수 없다.
비개발자 사용자에게 "커밋했습니다"와 "저장했습니다"는 다른 말이다.
프로필을 산출물에 녹여두면 사용자가 매 세션 다시 설명하지 않아도 된다.

## 수집 축 (비개발자 기준)

기술 축(언어·프레임워크 숙련도)은 비개발자에게 물어도 답을 못 한다. 대신:

1. **도메인 전문성** — 무슨 일을 하는 사람인가. 그 도메인 용어는 설명 없이 그대로 쓰도록.
2. **기술 노출 정도** — 터미널 사용 경험, 엑셀 함수/노코드 툴 경험, Git 개념 유무.
   → 작업자의 용어 선택을 결정 (커밋/저장, 배포/올리기 등). 산출물 용어사전의 "쓰지 말 것" 열을 채운다.
3. **설명 선호** — 결과만 / 이유까지. 배우고 싶은 사용자와 돌아가면 되는 사용자는 다르다.
4. **환경** — OS, 사용하는 AI 도구(Claude Code / Codex), 요금제.
   → 요금제는 토큰 예산 지침으로 바로 번역.
5. **결정 위임 범위** — "기술 선택은 알아서, 결과만 알려줘" vs "선택지 있으면 물어줘".
   비개발자 기본값은 전자. 산출물 "질문 규칙" 의 "묻지 않는 것" 범위를 결정한다.

## 구현 메모

- **프로필 수집 노드를 스펙 수집과 분리**한다. 한 번 만든 프로필을 다음 프로젝트에서 재사용 →
  사용자 피로와 Pro 요금제 토큰 모두 절약.
- **커밋되는 파일임을 전제**로 한다. 비개발자는 레포가 공개될 수 있다는 걸 모를 수 있다.
  프로필 섹션에는 역할·수준·선호만 넣고, 이름·소속·연락처는 빌더가 기본적으로 넣지 않는다.
- 산출물 구조: 본문은 AGENTS.md, CLAUDE.md는 `@AGENTS.md` 한 줄 (Codex·Claude 양쪽 호환).
- 프로필 질문은 `question-format.md` 의 질문 묶음 규격을 따른다 (2026-11-12 변경 — 이전: 한 번에 1개).
  한 번에 1개 규칙은 산출물의 작업자에게만 적용한다. 이유는 `design.md` "generate_artifacts".

## 산출물 섹션 예시 (개발자 버전 → 비개발자 버전 번역)

개발자 버전(루트 AGENTS.md)은 "LangGraph 개념 설명 불필요, Python 관용구 선택 시 이유 한 줄" 같은 기술 지침이다.
비개발자 버전은 예컨대:
- "사용자는 세무 업무를 한다. 회계 용어는 설명 없이 사용."
- "터미널 경험 없음. 명령어 대신 버튼/화면 기준으로 안내. 결과 보고 시 Git 용어 사용 금지."
- "기술 선택은 묻지 말고 결정 후 한 줄로만 알릴 것."
- "Claude Pro 사용. 한 작업에 대화 왕복 N회 이내 목표."

## 결정 (2026-11-14, 작업 단위 G)

- **질문:** 고정 질문 묶음 1개, 6문항, LLM 호출 0회. 문구·선택지·기본값은 `builder/prompts/interview_profile.json`.
  도메인 / 해 본 것(복수: 터미널·Git·엑셀이나 노코드·없음) / 설명 선호 / 결정 위임 / 운영체제 / AI 도구·요금제(복수).
  요금제는 도구에 달려 있어 한 질문으로 묶는다 — 한 묶음에는 서로 독립인 질문만 넣는다. 토큰은 묻지 않는다.
  축이 고정이라 요청마다 질문이 달라질 이유가 없고, 프로필은 다음 프로젝트에서도 쓰이므로 이번 요청에 맞춘 질문의 이득이 작다.
  "알아서 정해 주세요"·답 없음·"그만" 은 질문별 기본값 문장으로 채운다.
- **저장:** `~/.specbuilder/profile.json` (환경 변수 `SPECBUILDER_PROFILE_PATH` 로 바꿀 수 있음). 프로젝트를 넘어 재사용하고,
  레포 밖이라 커밋되지 않는다. 읽기·저장은 노드가 한다(`profile_store.py`) — CLI·API 는 프로필을 모른다.
  파일이 없거나 깨졌으면 다시 묻고 덮어쓴다. 파일에 모르는 키(이름 등)가 있어도 읽을 때 버린다.
- **입력으로 넣는 곳:** `interview_user` 에 결정 위임 범위(애매한 결정의 `decided_by` 경계), `select_stack` 에 환경,
  `generate_artifacts` 에 다섯 축 전부(작업자 컨텍스트 · 용어사전 "쓰지 말 것" · 질문 규칙의 "묻지 않고 정할 것").
- 프로필 문답은 `qa` 에 남기지 않는다 — `qa` 는 interview_user 의 문답 컨텍스트다.
- 이름·소속·연락처: 도메인 질문에 "적지 않아도 돼요" 를 붙이고 generate_artifacts 프롬프트가 옮기지 않게 한다.
  직접 입력에 섞인 이름을 코드로 걸러내지는 않는다.
